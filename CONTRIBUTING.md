# 参与维护 · Contributing

欢迎通过 Issue 或 Pull Request 改进文档、安装、检查脚本和打包。请说明问题、预期行为、应用版本及复现步骤；截图应裁去账号、对话和其他个人信息。

Issues and pull requests for documentation, installation, validation, and packaging are welcome. Include the problem, expected behavior, app version, and reproduction steps. Crop account details, conversations, and other personal information from screenshots.

宠物外观与动作是已确认的设计。修改图像前先讨论范围，不要为修正文案而重绘、调色或改变动画；机器状态名与显示文案分别处理。

The pet's appearance and animations are approved design choices. Discuss image changes first; documentation fixes should not redraw, recolor, or change motion. Treat machine state identifiers separately from display text.

面向用户的标题、步骤、表格和提示需中英对应；文件名、代码标识和产品专名不必重复翻译。所有修改应同时检查当前主分支和计划更新的发布附件。

User-facing headings, steps, tables, and messages should have matching Chinese and English text. File names, code identifiers, and product names need not be translated twice. Check both the current branch and any release assets being updated.

提交前运行 README 中的开发检查命令。动画修改还应在深浅背景和实际显示尺寸下目视检查；声明手机支持时，需要真实设备证据，不能仅依据浏览器缩小预览。

Before submitting, run the development checks in README. For animation changes, also inspect light/dark backgrounds and actual display sizes. Claims about mobile behavior require real-device evidence, not just a narrow browser preview.

不能用自动检查通过代替素材授权或视觉验收。第三方素材的权利边界见 [使用条款](LICENSE.md)。

Automated checks do not replace artwork permission or visual acceptance. See the [usage terms](LICENSE.md) for third-party rights boundaries.
